## Purpose and controlling decision

I, Bob Stewart, acting as EXOCHAIN principal and Chair, permanently remove
Cursor as a dependency of the EXOCHAIN application workstream.

For EXOCHAIN, no authority, work permission, stop condition, release gate,
credential gate, controller function, writer function, verification function,
evidence requirement, review requirement, CI condition, publication condition,
or successor-planning condition may depend on Cursor software, a Cursor
account, a Cursor credential, a Cursor agent, a Cursor task, a Cursor
transcript, a Cursor extension, a Cursor API, a Cursor provider interface, or
Cursor availability.

This decision is confined to EXOCHAIN. It does not uninstall, alter, disable,
or inspect Cursor system-wide; affect a non-EXOCHAIN project; access or change
any credential; or authorize inspection of process arguments, environment
values, browser storage, keychains, credential stores, or secret managers.

The historical exposure is separated from EXOCHAIN release governance. Any
enterprise account owner may remediate the unrelated credential under separate
security authority, but that activity:

- is not an EXOCHAIN task;
- is not an EXOCHAIN release gate;
- must not occur in an EXOCHAIN controller, writer, oracle, verifier, Council,
  CI, packaging, signing, publication, or deployment context;

  manifest, task, or review record; and
- must never return a credential value or fragment to EXOCHAIN personnel or
  tooling.

An enterprise-security action or its absence cannot stop, approve, reject, or
otherwise determine an EXOCHAIN workstream decision.

## Permanent EXOCHAIN Cursor-exclusion rule

Cursor is not an authorized EXOCHAIN execution or evidence surface. Effective
upon issuance:

1. No EXOCHAIN role may use Cursor to edit, execute, review, approve, attest,
   sign, publish, deploy, or relay release work.
2. No Cursor output may be accepted as fresh EXOCHAIN evidence. Existing
   Cursor-originated material, if any, is historical or imported context only
   until independently reproduced from bound source bytes by an authorized
   non-Cursor role.
3. No EXOCHAIN instruction, script, workflow, policy, checklist, lease,
   charter, or review may require a Cursor account, credential, extension,
   command, UI, API, agent, model, transcript, or provider readback.
4. Tool-neutral role names such as controller, writer, evidence oracle,
   evidence verifier, SPEC, QUAL, ADV, and VER identify separated functions,
   not a software vendor or agent product.
5. EXOCHAIN evidence must be reproducible from byte-bound inputs using
   repository-owned commands and ordinary local or CI runtimes that do not
   require Cursor.
6. A future EXOCHAIN plan or handoff that introduces a mandatory Cursor
   dependency is invalid and stops before execution. Reauthorizing Cursor for
   EXOCHAIN requires a later byte-bound principal directive that expressly
   supersedes this permanent exclusion; implication, convenience, or tool
   availability is insufficient.
