# EXOCHAIN 0.2.6 Security Remediation Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Close every actionable security boundary from code-review run 4,
record evidence-backed dispositions for all 86 formal findings and 52 design
observations, and prepare an internally consistent 0.2.6 release candidate.

**Architecture:** Remediate at the narrowest shared owned boundary: fail closed
for unaudited verification and authorization, use exact/checked deterministic
integer arithmetic, make secret-bearing APIs non-extractable and zeroizing,
bound inputs before allocation, and bind the release to one signed commit.
EXOCHAIN core/runtime-adapter changes and the LiveSafe adjacent changes remain in
separate commits and validation lanes.

**Tech Stack:** Rust 2024, Axum, Tokio, Serde/CBOR, BLAKE3, SQLx, WASM,
TypeScript/Node 20, Python packaging, Cargo/npm release tooling, GitHub Actions.

**Spec:** `docs/audit/exochain-code-review-report-run4-validation-2026-08-28.md`

- [ ] **Step 3: Implement exact deterministic arithmetic**

Use quotient/remainder decomposition, not a wider unavailable integer. The
helper is called only with denominator `10_000` and a numerator already
validated as at most `MAX_MULTIPLIER_BP`; overflow in the final mathematical
result retains the documented `u128::MAX` saturation policy:

```rust
fn mul_div_floor_saturating(value: u128, numerator: u128, denominator: u128) -> u128 {
    let quotient = value / denominator;
    let remainder = value % denominator;
    let fractional = (remainder * numerator) / denominator;
    quotient
        .checked_mul(numerator)
        .and_then(|whole| whole.checked_add(fractional))
        .unwrap_or(u128::MAX)
}
```

Call it from both economy basis-point helpers and multipliers. Preserve the
`0..=10_000` basis-point and `0..=100_000` multiplier validation at policy
boundaries. Use `saturating_add` for every exported diagnostics stage before
the existing saturating total. Add
`TenantError::UsageTotalOverflow { tenant_id: Uuid, field: &'static str }` and
the public checked APIs `UsageMeter::try_totals_in_window(...) -> Result<UsageTotals>`,
`UsageMeter::try_invoice(...) -> Result<Invoice>`, and
`TenantStore::try_total_bytes(...) -> Result<u64>`. Keep the existing public
`totals_in_window -> UsageTotals`, `invoice -> Invoice`, and
`total_bytes -> u64` signatures backward-compatible and make those methods
saturate at `u64::MAX`. Make `reconcile_bytes_with_store` use the checked store
and meter helpers, returning the contextual error for fields
`store_total_bytes`, `bytes_written`, or `api_calls` as applicable.
